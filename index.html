MODULE 01

Foundations & tooling

Give the page a meaningful HTML structure, link its stylesheet, and use the browser to see which declarations apply.

Build the document

Start with a doctype and a language. The head holds metadata, the tab title, and the stylesheet link. The body holds the visible page. For this example, styles.css sits beside the HTML file.

<!doctype html>
<html lang="en">
  <head>
    <meta charset="utf-8">
    <meta name="viewport" content="width=device-width, initial-scale=1">
    <title>Campus garden</title>
    <link rel="stylesheet" href="./styles.css">
  </head>
  <body>
    <main>
      <h1>Campus garden</h1>
      <p class="note">Open on Tuesdays.</p>
    </main>
  </body>
</html>

HTML reference

Comments
Write HTML comments with <!-- note --> and CSS comments with /* note */. HTML comments remain visible in the source.
Headings & landmarks
Use a descriptive h1 and nest heading levels by topic. Use header, nav, main, article, aside, and footer for the roles they describe.
Links & lists
Use an a with an href for navigation. Give it descriptive link text. Use ol for sequences, ul for unordered groups, and dl for terms and explanations.
Media
Give informative images meaningful alt text and decorative images alt="". Use native controls for audio and video, captions for video with speech or relevant sound, and a transcript for audio-only content.
Tables
Use tables for tabular data. Add a caption and mark headers with th and scope="col" or scope="row" in simple tables.
See a semantic HTML example 
<!-- Garden information -->
<section aria-labelledby="visit-title">
  <h2 id="visit-title">Plan a visit</h2>
  <ul>
    <li>Wear closed-toe shoes.</li>
    <li><a href="./map.html">Find the garden entrance</a></li>
  </ul>
  <table>
    <caption>Open hours</caption>
    <thead>
      <tr><th scope="col">Day</th><th scope="col">Time</th></tr>
    </thead>
    <tbody>
      <tr><th scope="row">Tuesday</th><td>9 a.m.–noon</td></tr>
    </tbody>
  </table>
</section>

Read the cascade

A type selector like p matches a tag, .note matches a reusable class, and #hours matches an ID that should be unique on the page. For ordinary author rules in the same layer, higher specificity wins. When competing rules tie on specificity and scope proximity, the later declaration wins. Text color and font family commonly inherit. Margins and padding generally do not.

p { color: #222; }
.note { color: #513898; }
.note { color: #452260; } /* Wins for p.note */

Use VS Code and Emmet to write markup. Inspect the Styles and Computed panels in DevTools to find overridden rules and final values. Keep keyboard focus visible with :focus-visible. Validate HTML and CSS, then use git status, git add, git commit, and git push to check, stage, record, and publish changes to your GitHub repository. Follow Canvas for course-specific Wakapi setup.

Which rule wins if an earlier #hours rule also sets the color?

The ID rule wins among these ordinary, same-layer author rules. Its specificity is higher than the class and type selectors. Confirm the result in DevTools.

MODULE 02

Box model & display

Predict an element’s size before measuring it. Start at the content and work outward through padding, border, and margin.

Content & padding
Content holds the text or media. Padding creates space between content and the border.
Border & margin
The border frames the padding and content. Margin sits outside the border and can create space between boxes. Adjacent vertical block margins can collapse in normal flow.
content-box
The declared width applies to the content. Add left and right padding and borders to find the border-box width.
border-box
The declared width includes content, padding, and border. Margin remains outside either sizing mode.

Measure a box

Content

width: 120px, border: 4px per side, padding: 12px per side. Border box: 152px. Content: 120px.

Block, inline, inline-block

A normal-flow block usually starts on its own line and fills the available inline width when width is auto. Inline text flows with its neighbors. Ordinary inline boxes ignore explicit width and height. Inline-block flows on a line and accepts dimensions. Use relative sizing such as % and rem where it fits the design. Try max-width: 100%; height: auto; for images that must shrink within a parent.

A box is 200px wide with 16px padding and a 2px border per side. What does DevTools measure?

Under content-box, the border box is 200 + 32 + 4 = 236px. Under border-box, it is 200px and the content is 164px wide. The element’s margins are outside both measurements.

MODULE 03

Display & positioning

Decide which elements should participate in normal flow before adding offsets, floats, or layout rules.

Static / relative
static is normal flow with no positioning offsets. relative keeps the original space and allows a visual offset. A relatively positioned parent can also anchor an absolutely positioned child.
Absolute / fixed
absolute leaves normal flow and commonly uses the nearest positioned ancestor for offsets. fixed also leaves flow and typically uses the viewport. Certain properties, such as an ancestor’s transform, can change the containing block.
Sticky / stacking
sticky keeps its flow space and sticks at an inset such as top: 0 within its scroll container and containing block. If boxes overlap, inspect their stacking contexts before changing z-index.
Floats / clears
float lets text wrap around a box. Use clear: both to start a block below earlier floats on either side. Use display: flow-root on a wrapper when it should enclose its floated children.
Flexbox
Lay out items along one main axis. justify-content distributes space along that axis, align-items aligns items on the cross axis, and flex-wrap allows another line. Changing flex-direction changes the axes.
.card { position: relative; padding: 3rem 1rem 1rem; }
.card-label { position: absolute; top: 1rem; right: 1rem; }

.actions {
  display: flex;
  flex-wrap: wrap;
  align-items: center;
  gap: 0.75rem;
}
An absolute label appears in the corner of the page. Where do you look first?

Inspect its containing block. If the intended card has no positioning, add position: relative to the card, then check the label’s offsets. Reserve room so the label and content can coexist on a narrow screen.

MODULE 04

Color & typography

Build a hierarchy readers can recognize and a text system they can read comfortably.

Give colors jobs

Assign colors to surfaces, body text, primary actions, secondary accents, and status. Choose a palette that fits the content and brand, then reuse it through CSS custom properties. Color meanings depend on context. Pair feedback colors with a text label or symbol.

  • Surface#F7F4FF
  • Text#241936
  • Action#5C35A4
  • Accent#F9A8D4

CSS accepts named colors, hex values, RGB channels, and HSL (hue, saturation, lightness). Alpha sets transparency in rgba(0, 0, 0, .25) or rgb(0 0 0 / 25%). Check a translucent color against its actual background. WCAG AA text contrast calls for at least 4.5:1 for normal text and 3:1 for large text.

Make paragraphs easy to follow

Choose typefaces with fallbacks. Use font size and weight for hierarchy, style for emphasis, and decoration to help identify links. Set a comfortable line length and line height, then use margins or a first-line indent to separate paragraphs. Adjust letter spacing carefully. Crowded letters, long lines, and inconsistent vertical gaps make text harder to follow.

.reading {
  font-family: "Source Sans 3", system-ui, sans-serif;
  font-size: 1rem;
  line-height: 1.6;
  max-width: 65ch;
}
.reading p + p { margin-block-start: 1em; }

When using Google Fonts, add the provider’s stylesheet link in the head and request the weights you use. Keep the fallback stack so the page remains readable when the web font is slow or unavailable.

How would you improve a paragraph that feels long, dense, and hard to scan?

Start with a shorter measure and more line height. Group ideas into shorter paragraphs, set a consistent gap, and check weight, size, and contrast on a narrow screen. Test at 200% zoom.

MODULE 05

CSS Grid

Use native Grid when rows and columns need to line up. Start small and add tracks when there is room.

Apply display: grid to a container. Its direct children become grid items. grid-template-columns and grid-template-rows define tracks. gap creates space between tracks. Grid lines mark track boundaries, and grid-column: 1 / -1 spans the whole explicit grid from its first to last column line.

fr divides available track space after gaps and other fixed sizing constraints. repeat() repeats track definitions, while minmax(0, 1fr) lets a fractional track shrink below an item’s intrinsic minimum. Long content may still need wrapping.

.cards {
  display: grid;
  grid-template-columns: minmax(0, 1fr);
  gap: 1rem;
}
@media (min-width: 42rem) {
  .cards { grid-template-columns: repeat(3, minmax(0, 1fr)); }
}

Compare narrow and wide layouts

NewsCalendarContact

Preview mode: Wide container. On a small screen the preview can still stack to fit.

Why does grid-template-columns: 2fr 1fr leave room for the gap?

Grid subtracts the gap before sharing the available track space. With 600px to fill and a 24px gap, 576px remains. If item sizes impose no extra constraints, the tracks measure 384px and 192px.

MODULE 06

Bootstrap & publishing

Choose what to reuse, read the documentation for the version you load, and test the published build.

Read Bootstrap markup

Add Bootstrap’s CSS from its official starter and place your overrides after it. Load the matching Bootstrap bundle for interactive components such as a collapsing navbar or an offcanvas sidebar. The default Bootstrap grid uses Flexbox and a 12-column span system. A .container sets responsive widths, .row holds columns, and .g-3 sets the gutters.

<div class="container">
  <div class="row g-3">
    <div class="col-12 col-md-8">Main content</div>
    <div class="col-12 col-md-4">Related links</div>
  </div>
</div>

Both columns span the full row on small screens. At Bootstrap’s md breakpoint and above, the columns share the row in an 8-to-4 ratio.

Buttons
Combine .btn with a variant such as .btn-primary. Use button for actions and a href="…" for navigation.
Navbars & sidebars
A collapsing navbar pairs a toggler with a matching target ID. A sidebar can use a semantic nav or aside, and Bootstrap Offcanvas can turn it into a drawer. Check the trigger label, keyboard focus, and mobile behavior.
Other dependencies
Bootstrap supplies a design framework. jQuery is a JavaScript library. Google Fonts supplies web fonts, and Font Awesome supplies icons. Match Font Awesome markup to its version, such as fa fa-star in v4 and fa-solid fa-star in v6. Give icon-only controls an accessible name.
Dependency delivery
A CDN serves files directly. npm and Yarn install and track packages for projects with a dependency workflow. Bower appears in older projects and course material. Check the docs, licenses, versions, and required CSS or JavaScript before choosing a dependency.
Inspect a Bootstrap navbar and button

This component assumes the starter’s CSS and JavaScript bundle are loaded. Match the toggler’s data-bs-target and aria-controls to the collapse ID.

<nav class="navbar navbar-expand-md" aria-label="Garden">
  <div class="container">
    <a class="navbar-brand" href="./">Campus Garden</a>
    <button class="navbar-toggler" type="button"
            data-bs-toggle="collapse" data-bs-target="#garden-menu"
            aria-controls="garden-menu" aria-expanded="false"
            aria-label="Toggle garden navigation">
      <span class="navbar-toggler-icon"></span>
    </button>
    <div class="collapse navbar-collapse" id="garden-menu">
      <div class="navbar-nav">
        <a class="nav-link" href="#hours">Hours</a>
      </div>
      <a class="btn btn-primary ms-md-auto" href="./map.html">
        View garden map
      </a>
    </div>
  </div>
</nav>

For a slide-out sidebar, use the Bootstrap Offcanvas pattern with a named panel and a close control.

Publish through GitHub Pages

Push the site files, choose a publishing source in the repository’s Pages settings, and put index.html at that source’s root. Open the Pages URL in a fresh browser session. For a project site, prefer paths such as ./styles.css and match filenames exactly, including capitalization.

Your Bootstrap navbar styles look right, but its toggle does nothing. What do you check?

Check that the matching Bootstrap bundle loads and that data-bs-target matches the collapse element’s ID. Use DevTools Network and Console to spot a missing file or script error. Then verify the toggle with the keyboard.

MODULES 07–08

Review & finals

Predict the result before expanding each answer. Then explain the rule out loud or reproduce the behavior in a small local practice page.

A stylesheet is missing on Pages, but the HTML loads. What do you inspect?

Check the requested CSS URL in DevTools Network for a 404. On a project site, /styles.css points at the domain root, while ./styles.css resolves beside the HTML page. Confirm the file is committed to the Pages source and its name matches the link exactly.

Why can a 100% wide input overflow its container?

With content-box, the content alone can occupy the full available width. Padding and border add to it. Apply box-sizing: border-box and inspect whether margins or other rules also contribute.

Which tool fits each task: wrapped image, button row, card collection, or corner label?

Use a float for text around the image, Flexbox for the button row, Grid for aligned card columns and rows, and absolute positioning inside a positioned parent for the corner label.

A design uses pale text and a red border as the only sign of an error. How would you improve it?

Increase the text contrast against its surface and add a clear error message tied to the problem. Check keyboard focus, test at 200% zoom, and verify the message is still visible in a narrow layout.

A three-column design clips long links on a phone. What do you change and retest?

Start with one column at narrow widths. Set flexible tracks and allow long links to wrap, for example with overflow-wrap: anywhere. Use DevTools to find the overflowing element and retest at narrow, medium, and wide widths.

Independent practice

Make a small event page with a header, a main article, a related-links area, and a footer. Link an external stylesheet, build a readable type scale and palette, then use Grid to stack the content on a phone and place the related links alongside the article when there is space.

  • Tab through the page to confirm focus is visible and links follow a sensible order.
  • Resize the viewport, try 200% zoom, and check that nothing important clips or overlaps.
  • Validate the HTML and CSS, and explain one issue you found and how you fixed it.
